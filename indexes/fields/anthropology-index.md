### 全体像

この3コースは、一般的な人類学の全領域を網羅するものではない。中心にあるのは次の交差領域である。

1. 文化とアイデンティティが物・儀礼・映像に現れる過程  
2. 観察と表象が知識を構成する過程  
3. 植民地主義や歴史的不正義に対する責任と回復  
4. 記録、証拠、メディア、社会運動の関係

## 使える武器

### 1. エスノグラフィックな現場観察

**使い方**

- 業務マニュアルに書かれていない例外処理、暗黙のルール、役割分担を観察する。
- 「顧客が何と言ったか」だけでなく、「実際に何をしているか」を見る。
- 個別行動を、制度・文化・物理環境・他者との関係の中で解釈する。

**ビジネス例**

- 倉庫の自動化案件で、作業員がシステムに記録されない確認作業をどこで行っているかを観察する。
- 病院の予約システム改善で、患者、受付、看護師、医師が同じ予約情報をどう異なる意味で扱っているかを調べる。
- コンサルティングで、KPIが悪い原因を個人の能力不足と決めつけず、ツール、権限、顧客対応、組織文化まで調査する。

### 2. 「Ways of Seeing」によるフレーミング監査

同じ出来事でも、どの視点を採用するかで問題の定義が変わる。

**使い方**

- 経営者、現場担当者、顧客、規制当局、影響を受ける第三者の視点で同じプロセスを記述する。
- ダッシュボード、KPI、AIモデルの出力が何を可視化し、何を不可視化しているかを確認する。

**ビジネス例**

- AI画像検査で不良品判定が多い場合、モデルの性能だけでなく、照明、カメラ位置、撮影対象の偏りを検証する。
- 顧客満足度が高いのに解約率が高い場合、アンケート回答者だけでなく、回答しない顧客やサポート担当者の視点を追加する。
- 経営会議の資料について、「数字に現れない待ち時間、感情的負担、例外対応」を別レイヤーで可視化する。

### 3. インタビューと映像記録による顧客調査

DV Labのインタビュー、撮影、音声、Film Grammarは、定性的な顧客調査に応用できる。

**使い方**

- 誘導質問ではなく、具体的な出来事を語ってもらう。
- 発言だけでなく、操作順序、躊躇、周囲の人、使っている道具を記録する。
- インタビュー映像を、問題発見・仮説形成・社内共有に使う。

**ビジネス例**

- SaaS導入調査で「使いやすいですか」と聞く代わりに、実際の請求処理を画面共有してもらう。
- 新製品のユーザーインタビューを、発言集ではなく「状況→行動→障害→代替手段」の短いケース映像にする。
- 営業組織の属人ノウハウを、熟練者の商談記録とインタビューから標準化する。

### 4. 映像を使った業務プロセス分析

カメラ、音声、照明の知識は、業務の可視化と自動化候補の発見に使える。

**ビジネス例**

- 製造現場を複数の角度から撮影し、作業の手戻り、待ち時間、物の受け渡しを抽出する。
- コールセンターの音声と画面操作を同期させ、顧客の不満が発生するタイミングを特定する。
- 現場映像から、完全自動化ではなく「判断支援」「確認作業の自動化」に向く部分を切り出す。

**注意点**

- 従業員の同意、顔・音声の個人情報、撮影による行動変化を管理する必要がある。
- 映像は客観的な現実そのものではなく、撮影条件によって偏る。

### 5. 物質文化と文化的記号による市場理解

「Merchant of Art」やヘナ芸術の事例から、商品を機能だけでなく文化的記号として分析できる。

**ビジネス例**

- 南アジア系コミュニティ向けの結婚関連サービスで、装飾、贈答、家族間の承認を単なる嗜好ではなく、社会的関係の表現として設計する。
- 海外展開するブランドで、色、包装、素材、儀礼的な使用場面が現地でどのような意味を持つか調べる。
- 「高級」「伝統的」「本物らしい」といったブランド表現が、誰の文化を消費しているのかを点検する。

### 6. ディアスポラを前提にしたセグメンテーション

国籍や居住地だけではなく、移民ネットワーク、家族関係、言語、儀礼、送金、オンラインコミュニティを単位に顧客を理解する。

**ビジネス例**

- フィンテックの顧客分類を「パキスタン人」ではなく、送金先、家族行事、都市間ネットワーク、言語利用などの実践で分ける。
- 移民二世・三世がどの文化要素を維持し、どの要素を再解釈しているかを調べ、商品設計に反映する。
- グローバル製品のローカライズで、翻訳だけでなく利用場面と社会的意味を設計する。

### 7. アーカイブと証拠のプロヴナンス管理

アーカイブを社会運動の資源として扱う視点は、企業の記録管理やAIデータの来歴管理に転用できる。

**ビジネス例**

- AI学習データについて、誰がいつ、どの条件で収集し、どの権利・同意に基づくかを記録する。
- ESGやサステナビリティの主張を、社内資料だけでなく、地域住民、労働者、第三者記録で突き合わせる。
- M&Aのデューデリジェンスで、公式資料と現場証言、過去の行政記録を比較する。
- 古い意思決定の経緯を追跡し、現在のシステム上の責任者だけに過去の問題を押しつけない。

### 8. 移行期正義・賠償を応用したAI／製品被害の回復設計

「賠償とは何か」という問いは、単なる返金以外の被害回復策を設計する際に有用である。

**AIプロダクトの例**

顔認識や採用AIが特定集団に不利益を与えた場合、対応を以下に分解する。

- 事実の承認と説明
- 金銭的補償や返金
- 影響を受けた人へのサービス回復
- モデルやデータの修正
- 独立監査
- 再発防止のガバナンス
- 被害を受けた当事者が意思決定に参加する仕組み

「モデル精度を上げれば終わり」ではなく、責任、承認、回復、再発防止を別々に設計できる。

### 9. 責任分解とエスカレーション設計

国家責任や国際機関・裁判所に関する講義は、複雑な問題で責任主体を分ける際の枠組みを提供する。

**ビジネス例**

- サプライチェーン上の人権侵害について、委託先だけでなく、発注企業、監査会社、プラットフォーム、規制当局の責任を整理する。
- 個人情報漏洩時に、開発者、データ提供者、プロダクト責任者、経営陣の責任と意思決定権をマッピングする。
- 問題が社内で解決できない場合の第三者機関、監査、規制当局へのエスカレーション経路を事前に設計する。

### 10. ステークホルダー動員の設計

植民地過去の承認を求める運動の分析は、複数の当事者を組織化する際に役立つ。

**ビジネス例**

- 新しいデータ利用方針を作る際、顧客、従業員、研究者、地域団体、規制当局を別々の利害関係者として整理する。
- ESG施策で、企業の一方的な「支援」ではなく、被影響者が議題設定と評価に参加する仕組みを作る。
- 社内改革において、個別の苦情を組織的なパターンとして可視化し、経営層に届く証拠形式へ変換する。

| HCI・UXリサーチ | 観察、インタビュー、コンテクスト・オブ・ユース | ユーザーが実際に製品を使う場面を記録し、要件定義やプロトタイプに反映する |
| サービスデザイン | ジャーニー、タッチポイント、共創、ペルソナ | 顧客体験を個別画面ではなく、制度・従業員・物理環境を含むサービス全体で設計する |
| AI・データサイエンス | データバイアス、ラベル、データ来歴、モデルの可視性 | 「誰が見えていて誰が見えないか」を学習データ、評価指標、カメラ配置、運用現場に適用する |
| オペレーションズ | プロセスマッピング、ボトルネック、例外処理 | 映像観察から暗黙作業や手戻りを発見し、自動化・標準化の対象を決める |
| マーケティング | 文化的記号、アイデンティティ、ブランド真正性 | ローカライズ、ブランド設計、コミュニティマーケティング、文化的盗用の回避 |
| 組織行動論 | 非公式規範、権限、役割、組織文化 | 「制度上の業務」と「実際の仕事」の差を把握し、変革施策の失敗要因を特定する |
| 倫理・ESG | 被害、責任、承認、救済、再発防止 | AI事故、サプライチェーン問題、顧客被害への対応を返金だけで終わらせない |
| 心理学・意思決定 | フレーミング、物語、認知バイアス | 同じデータが経営者・現場・顧客にどう異なる判断を引き起こすかを分析する |

### 重要な接続原則

人類学の強みは、一般化された指標やモデルに落とす前の段階で、次を明らかにすることにある。

- 数字に現れない行動と意味
- 制度と実際の運用のずれ
- 製品や技術が埋め込まれる文化的文脈
- 誰の視点が意思決定から排除されているか
- 過去の責任が現在の信頼・正当性にどう影響するか

したがって、AI、コンサルティング、自動化、組織変革においては、人類学を「定量分析の代替」として使うより、**問題設定・現場理解・ステークホルダー設計・被害回復の前段に置く**のが最も有効である。
