# 離散カード構造で連続・確率・創発・自己言及・文脈を扱う設計

先に全体を貫く洞察を一つ。あなたの5つの苦しみは、実はすべて同じ根から来ています。**「カード＝知識の全体」だと思うと苦しい。「カード＝外部にある実行可能モデル・分布・プロセスへの離散的な参照＋要約」と再定義すれば、すべて実装可能になる**。これはOOPで言えば、クラスに全ロジックを書くのではなく、ハンドル（参照）と契約（インターフェース）だけを持たせる設計です。

以下、各領域ごとに設計を示します。

---

## 1. 連続性の記述 — 「定性状態への離散化 + 実行可能モデルへのポインタ」

### 参考理論
- **定性物理学（Qualitative Physics）**: Forbus の Qualitative Process Theory、Kuipers の **QSIM**。連続系を「ランドマーク値」と「定性状態（増加/減少/定常）」に離散化する手法は30年の蓄積があります
- **ハイブリッドオートマトン**: 離散モード + モード内の連続ダイナミクス、という二層構造

### 設計方針
微分方程式そのものをグラフに「翻訳」しようとしない。カードが持つのは：
1. **定性的レジーム（相）の集合** — 人間の推論に使う離散版
2. **実行可能モデルへの参照** — 精密な値が必要なときに呼ぶ

### スキーマ例

```yaml
card: 熱伝導
definition: "温度勾配に比例して熱が移動する現象"
dynamics_spec:
  model_ref: "models/heat_eq.py#FourierLaw"   # 実行可能な微分方程式
  variables: [T(x,t), k, ρ, c]
  qualitative_states:                          # QSIM式の離散化
    - id: transient
      condition: "∂T/∂t ≠ 0"
      landmarks: [T_initial, T_ambient]
    - id: steady_state
      condition: "∂T/∂t ≈ 0 (|∂T/∂t| < ε)"
  transitions:
    - from: transient
      to: steady_state
      driver: "t → ∞, 時定数 τ = L²/α"
boundary_conditions:
  - "連続体近似が成立（平均自由行程 << 系のサイズ）"
```

### アルゴリズム
- グラフ走査・関係推論は `qualitative_states` レベルで行う（「加熱し続けると定常状態に遷移する」はカードだけで答えられる）
- 「120秒後の温度は？」のような定量的質問が来たら `model_ref` をサンドボックス実行し、**結果をカードにキャッシュせず、クエリログに記録**する（後述の観測問題対策）
- 遷移条件はメソッドの事前条件と同型なので、既存の Boundary Conditions 機構をそのまま流用できる

### 実用ライン
理想的には全カードにシンボリックなODEを持たせて記号微分・数値解析を統合したいが、実用上は**「レジーム3〜5個 + ランドマーク値 + 遷移条件」の定性表現で、人間向け推論の9割は賄える**。実行可能モデルは需要の高いカード（熱・拡散・指数成長など上位50概念程度）にだけ付ければよい。

## 2. 確率・不確実性 — 「Boundary Conditions の三層化 + プロトタイプ空間」

### 参考理論
- **概念空間理論（Gärdenfors, Conceptual Spaces）**: 概念＝特徴空間内の凸領域。境界は線ではなくグラデーション
- **プロトタイプ理論（Rosch）**: カテゴリは必要十分条件ではなく典型例からの距離で定義される
- **ファジィ集合（Zadeh）／ラフ集合（Pawlak）**: 前者は帰属度、後者は「確実に属する下近似／属しうる上近似」の二領域
- 推論エンジン側は **Probabilistic Soft Logic (PSL)** や **Markov Logic Networks** が参考になる

### 設計方針
Boundary Conditions を単一のブール条件リストではなく、**三層構造**にする：

```yaml
boundary_conditions:
  hard:          # ラフ集合の「下近似」— 破れたら確実にこの概念ではない
    - "系にエネルギー入力がある"
  soft:          # 帰属度に寄与する重み付き条件
    - predicate: "変化がべき乗則に従う"
      weight: 0.7
      source: "文献X / 経験則"
    - predicate: "臨界点近傍である"
      weight: 0.9
  prototype:     # 埋め込みベクトル + 典型事例
    embedding: [0.12, -0.4, ...]
    exemplars: [instance_042, instance_117]
  membership_fn: "sigmoid(Σ w_i · match_i - θ)"   # 帰属度の計算式
```

### アルゴリズム（帰属判定）
1. `hard` を全チェック → 1つでも破れたら帰属度0（枝刈り）
2. `soft` の重み付き和 + プロトタイプとのコサイン類似度で帰属度 μ ∈ [0,1] を算出
3. **「AでもありBでもある」は排他ではなく、複数カードへの帰属度ベクトルとして返す**: `{相転移: 0.8, 緩和現象: 0.6}`。逆引き（属人知→科学概念）では上位k件を確信度付きで提示する
4. 関係エッジにも確信度を付ける: `depends_on(A, B, confidence=0.85, provenance=...)`。グラフ走査時は確信度の積が閾値を切ったら打ち切る（これは自然な探索深度制御にもなる）

### 実用ライン
理想は全カード上のベイジアンネットで一貫した確率推論だが、キャリブレーションコストが非現実的。実用上は **hard/soft の二値+重みで十分**で、重みは厳密な確率でなく「順位付けが正しくなる程度の序数的スコア」と割り切る。フルの確率推論は、矛盾検出が必要なホットスポット（頻繁に誤分類が起きるカード群）にだけ局所的にPSLを適用する。

## 3. 創発 — 「事前予測を諦め、事後検出＋現象カードの鋳造」

### 参考理論
- **シナジェティクス（Haken）の秩序パラメータ**: 創発の検出＝「少数のマクロ変数で系が記述できるようになる瞬間」の検出
- **計算力学（Crutchfield, ε-machine）**: 振る舞いのログから最小の因果状態機械を再構成する
- **ネットワークモチーフ検出**: どの部分グラフ構造が繰り返し「一緒に活性化」するか
- Holland の *Emergence* — 創発は構成則からは演繹できないが、**記録・命名は可能**という立場

### 設計方針
創発はカード間の合成から演繹しようとすると原理的に詰む（それが創発の定義だから）。代わりに**「使用ログとシミュレーションから、既存カードで説明できないマクロパターンを検出し、新しい現象カードとして鋳造する」パイプライン**を作る。

### データ構造とパイプライン

```yaml
# ① 共活性化ログ（すべてのクエリで記録）
activation_log:
  query_id: q_20250114_001
  activated_cards: [自己組織化, フィードバック, 閾値]
  co_occurrence_context: "在庫管理の発振問題"

# ② 検出された創発候補
emergence_candidate:
  constituents: [個体の単純規則, 局所相互作用, 密度]
  interaction_topology: "近傍結合・非線形"
  macro_observable: "集団としての秩序だった運動"   # 秩序パラメータ
  detection_method: "co-activation mining"        # or "simulation"
  novelty_score: 0.82    # 既存カードのどの組み合わせでも説明率が低い
  status: pending_curation

# ③ 昇格後の現象カード（通常カードと同型 + 由来を持つ）
card: 群れ行動
type: emergent_phenomenon
emerges_from:                    # 新しい関係タイプ
  constituents: [整列規則, 分離規則, 結合規則]
  scale_gap: "個体 → 集団"
  grounding_trace: sim_run_0042  # 再現可能なシミュレーション記録
```

### アルゴリズム
1. **共活性化マイニング**: 頻出するカードの組 `{A, B, C}` で、その組み合わせに対応する既存カードが存在しない（グラフ上で共通の親・現象カードを持たない）ものを抽出 → 「概念の穴」候補
2. **シミュレーション検証（余裕があれば）**: 構成カードの `model_ref` をエージェントベースモデルとして合成実行し、構成要素の変数だけでは予測できないマクロ変数（相関長の発散、分布の変化）が出るか検定
3. **人間キュレーションゲート**を必ず通してカード化する。`emerges_from` は `has_part` とは別の関係タイプにする — 部分の性質から親の性質を継承推論してはいけない（**創発関係は継承を遮断するアノテーション**として機能させる）

### 実用ライン
理想はε-machine的な自動的因果状態再構成だが、実用上は**「共活性化マイニング → novelty スコアリング → 人間承認」の半自動パイプラインで十分**。重要なのは検出精度より、「創発された現象に名前とカードを与え、`emerges_from` で由来を辿れるようにする」記録機能。創発の**予測**は諦め、**捕捉と索引付け**に徹する。

## 4. 観測問題 — 「層の分離 + バイテンポラル + 昇格パイプライン」

### 参考理論
- **タルスキの言語階層**: 自己言及のパラドックスは対象言語とメタ言語の分離で回避する — これがそのままアーキテクチャ指針になる
- **CQRS / イベントソーシング**: 読み取りモデルと書き込みモデルの分離
- **バイテンポラルデータモデル**: 有効時間（知識がいつ正しかったか）とトランザクション時間（いつ記録されたか）の二軸
- **Goodhartの法則 / 多腕バンディット**: 使用頻度を指標にすると指標自体が歪む問題と、その緩和策

### 設計方針
「検索が知識基盤を変える」こと自体は望ましい（学習するシステム）。危険なのは**無制御なループ**。制御は3つの分離で行う：

```
┌─ L2: メタ層（使用統計・ランキング重み・確信度更新）── 自動更新OK
├─ L1: 構造層（カード本体・関係）──────── 昇格パイプライン経由のみ
└─ L0: 台帳層（追記専用イベントログ）───── 不変・全履歴
```

### 実装

```yaml
# すべての変更はイベントとして追記（L0）
event:
  type: card_auto_generated
  card_id: c_0912
  trigger_query: q_20250114_001
  transaction_time: 2025-01-14T10:32
  valid_time: 2025-01-14T10:32
  provenance: {method: gap_detection, confidence: 0.6}

# 自動生成カードは即座に本番グラフに入れず staging へ
staging_graph:
  promotion_criteria:
    - confidence > 0.8
    - 3回以上の独立クエリで有用と評価
    - 既存カードとの矛盾検査パス
    - (高影響カードは) 人間承認
```

### ループ制御の具体策
1. **使用統計は内容を変えない**: L2 の使用頻度・共活性化はランキングと探索優先度にのみ影響し、Definition や Relations（L1）には触れない。L1 の変更は必ず昇格パイプラインを通る
2. **減衰と探索**: ランキングへの使用頻度の寄与に時間減衰を入れ、ε-greedy（例: 10%のクエリでは人気度を無視して探索）で「使われるほど使われる」正帰還の暴走を防ぐ
3. **スナップショット固定**: クエリには `as_of` パラメータを持たせ、任意時点のグラフ状態で再現実行できるようにする。「あの推論はなぜあの結論を出したか」の監査が可能になる
4. **自動生成の連鎖に深度制限**: 自動生成カードがさらにカードを自動生成する連鎖は深度2で打ち切り、人間ゲートを挟む（無限の自己増殖を防ぐ）

### 実用ライン
理想は完全なリフレクティブアーキテクチャ（Maes流の自己記述システム）だが、実用上は**「追記専用ログ + staging→本番の二段階 + as_of スナップショット」の3点セットで自己言及は十分制御できる**。これは要するにデータベース工学の枯れた技術（イベントソーシング＋バイテンポラル）の適用であり、哲学的難問を工学的定番解に還元できる領域。

## 5. 文脈依存性 — 「不変コア + 文脈デルタ（マイクロセオリー方式）」

### 参考理論
- **Cyc のマイクロセオリー**: 巨大知識ベースを文脈ごとの整合的な部分理論に分割し、`ist(context, proposition)` で「文脈cにおいてpが成り立つ」を表現（McCarthy の文脈形式化）
- **RDF Named Graphs / C-OWL**: 同一リソースに文脈別のグラフを重ねる標準技術
- **概念空間理論（再登場）**: 同じ概念でも文脈により特徴次元の**顕著性重み**が変わる、というモデル化

### 設計方針
OOPのポリモーフィズムの比喩は正しいが、**継承（文脈ごとにサブクラス）ではなくデルタ合成（コア + 文脈別差分）**で実装する。継承だと文脈が増えるたびにクラス爆発するが、デルタなら共有部分が一箇所に保たれる。

### スキーマ

```yaml
card: エントロピー
core:                                  # 文脈不変の内核
  definition: "系の取りうる微視的状態数の対数（に比例する量）"
  invariant_relations:
    - is_a: 状態量
facets:                                # 文脈別デルタ
  physics:
    definition_delta: "S = k_B ln W。熱力学第二法則により孤立系で非減少"
    salience: {可逆性: 0.9, 温度: 0.9, 情報: 0.3}
  information_theory:
    definition_delta: "H = -Σ p log p。符号化の下限を与える"
    salience: {圧縮: 0.9, 確率分布: 0.9, 温度: 0.1}
    terminology: {W: "シンボル数", S: "H"}
  business:
    definition_delta: "組織・プロセスの無秩序度の比喩。放置すると増大する"
    epistemic_status: analogy          # ← 比喩であることを明示！
    salience: {劣化: 0.8, メンテナンスコスト: 0.7}

# 文脈自体もカード（文脈グラフに継承関係を持たせる）
context: business
  is_a: applied_context
  default_epistemic_status: analogy_tolerant
```

### 解決アルゴリズム

```python
def resolve(card, context):
    facet = card.facets.get(context) \
            or card.facets.get(context.parent)   # 文脈継承で探索
    return merge(card.core, facet)               # コア + デルタ合成
```

- グラフ走査も文脈でフィルタされる: `business` 文脈では `epistemic_status: analogy` のエッジを辿ってよいが、`physics` 文脈からの推論では比喩エッジを遮断する。**これが「ビジネス比喩が科学推論にコンタミする」事故の防止弁になる**
- 逆引き（属人知→概念）では、入力テキストから文脈を推定してから該当ファセットの埋め込みとマッチングする

### 実用ライン
理想はMcCarthy流の完全な文脈論理（文脈間の含意関係まで形式化）だが、実用上は**正準文脈を3〜5個（例: 科学/工学/ビジネス/日常）に固定し、デルタ+顕著性重み+epistemic_status の3点で運用すれば十分**。文脈の無限細分化は避け、「この2文脈で意味が割れたら初めてファセットを追加する」遅延分割ポリシーにする。

## 統合設計原則

5つの解を貫く原則を抽出すると：

**原則1: カードは「知識そのもの」ではなく「知識への離散インターフェース」**
連続系（→実行可能モデル参照）、分布（→帰属関数）、創発（→シミュレーショントレース）、いずれも本体は外部にあり、カードは要約・契約・ポインタを持つ。OOPで言えば、全ロジックをクラスに書くのではなく、ハンドルとインターフェースを持たせるファサード設計。

**原則2: すべての主張に「確信度・出所・認識論的地位」の3つ組を付ける**
`(confidence, provenance, epistemic_status)` を関係エッジ・境界条件・ファセットの全レベルで持つ。これが確率（2）、創発候補の管理（3）、昇格判定（4）、比喩の遮断（5）を単一機構で支える。

**原則3: 層を分離し、層間の情報流に関門を置く**
台帳層／構造層／メタ層（4）、コア／ファセット（5）、hard／soft境界条件（2）、定性状態／定量モデル（1）— すべて「安定した不変部分」と「流動的な可変部分」の分離。自動プロセスは可変層を自由に更新でき、不変層への昇格には検証ゲートが要る。

**原則4:
