## 背景

OOP的な構造で世界のあらゆるもの（知識・行動・物理・意味）を記述する「自律成長型知識基盤」を構築しています。

### 現在のシステム
- 概念カード33枚（経済学10、CS10、数学/統計13）、perspectives 4本
- MIT OCW 4,258講義の検索基盤（BM25、SQLite FTS5）
- カード構造：Definition, Mechanism, Boundary Conditions, Failure Modes, Business Transfer, Related Concepts
- 三層リンク：perspectives → concepts → MIT OCW講義
- 自動増殖：回答後に未カード化概念を_inbox/に自動生成
- 昇格ルール：AI草案(_inbox/)→ ユーザー確認 → 確定(concepts/)

### 直前の評価結果
- 検索のRecall@6 = 6.0%（50問中3問しかヒットしない）
- 原因：BM25のAND検索が厳しすぎ、言い換え・シナリオ問題は全滅

### 設計レビューで合意済みの方向
以下5つの「苦しい領域」に対して、Fable5とGPT-6 Astraが設計提案を出し、採用方針を決めた。

1. **連続性** → 定性レジーム + model_ref（Fable5案）
2. **確率・不確実性** → TruthValue型システム + 不確実性4分類（Astra案）
3. **創発** → 共活性化マイニング + CompositionCard（両方合成）
4. **観測問題** → Snapshot + Event Sourcing + 由来DAG + 循環防止（Astra案）
5. **文脈依存性** → core + delta + Facet/Lens分離（両方合成）

### 統合設計原則（両者一致）
- カードは知識そのものではなく、モデルへのハンドル/インターフェース
- 層を分離する（不変層 / 可変層 / メタ層）
- すべての主張に確信度・出所・文脈を付ける
- 創発は予測を諦め、事後検出＋記録に徹する
- 自動生成は即時採用せず、候補層を通す

## 問い

この設計を、**今あるシステム（カード33枚、BM25検索、MIT OCW基盤）から実際に動くシステムへ進化させる**ために、どういう順番で何を実装すべきか？

### 回答の条件

1. **実装フェーズを分けて、各フェーズで「何が動くようになるか」を明示する**
2. **各フェーズの工数感を示す**（1人のフルスタックエンジニアがAIツールを駆使する前提）
3. **最初のフェーズは「今のシステムから最小の変更で最大の改善が得られるもの」にする**
4. **理想の完成形に至るまでの依存関係を示す**（何が何に依存しているか）
5. **「ここまで来たら売れる」「ここまで来たら研究として発表できる」のマイルストーンを示す**
6. **やらなくていいこと（過剰設計になるもの）も明示する**
