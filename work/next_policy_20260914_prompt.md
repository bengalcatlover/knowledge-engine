# あきらぐ：低コスト化後の次の方針レビュー

ユーザーがFable 5とGPT-6 Astraの両方に次の方針を聞くことを明示依頼した。同一の資料をそれぞれに渡している。今回は助言のみ、実装・公開・カード承認は行わない。相手の回答を予想せず独立に判断してほしい。

## ユーザーの目的・制約

根拠を追跡できる世界モデルを自律的に成長させる「知識OS」。基礎科学→科学→宇宙（適用モデル）→オブジェクト→実践の5層。人が毎回情報を供給しなくても、欠落発見→情報収集→検証→構造化→再利用を回したい。
通常の実作業は安いAIとPythonで行う。旧世代・小型モデルも選択肢。高額モデルは今回のような明示依頼の設計レビューに限定し、自動エスカレーションしない。

- 直近1サイクルでclaim 105→107、edge 49→50。増分は未検証claim2件とHYP_EDGE1件。検証済みclaimは増えていない。40ノード中17 approved、22 proposed、1 blocked。
- 6領域: 第二価格オークション、情報理論、メカニズムデザイン、情報経済学、契約理論、ベイズ意思決定。

- gap: open17、resolved6。G1未支持claim、G2欠落instance、G3未検証edge。

## 実装と既知の限界

- 7フェーズ: repair→extract→grow→relate→promote→expand→audit。
- repairはgap検出が中心で自動的な根拠充填は未接続。expandのfrontier_managerは未実装、従来は100ノード到達後の予定だった。
- DOI実在照合とabstract取得は外部学術API。DOIの実在はclaimの正しさを証明しない。
- 生成・抽出・分類・関係候補をHaiku 4.5からGPT-4.1 nano固定の共通窓口へ変更。入力全文等のハッシュでキャッシュ。1プロセス最大20 calls、最大2048 output tokens、40000 UTF-8 bytes、概算費用予約$0.05。LLM失敗時再試行・高額fallbackなし。外部文献APIの総時間・予算はまだ厳密に連動していない。
- lowで最大5 evidence mining、ノード生成入力最大3 evidence、新ノード最大5。キーワード重複判定・帰属はPython。
- nanoの試験で否定・対象範囲の保持、既存ノードへの吸収、無関係ペアの棄却はできた。一方で先行研究をown_resultに誤分類、途切れた文の補完、非有意をrefutesに分類、subjectsに例示文字列を出す問題が出た。
- 対策: 原文と一致するsource_quote必須、途切れた文を使わない指示、hypothesisはspeculativeへ固定、refutesはreview_required、backgroundは登録保留、例示subjects除去。再評価で先行研究のbackground分類と途切れた文の除外は改善したが、科学的分類全般の精度は未証明。原文一致は意味的含意の証明ではない。
- 新規関係は全て[HYP_EDGE]タグ。これはrationaleの文字列タグであり、全下流の探索・推論・昇格から機械的に除外されることは未検証。新ノードはproposed。orchestratorのpromoteはdry-runに変更。
- 契約テスト9件、workerテスト9件、DB integrity_check合格。ただし科学的正しさ、全下流の候補隔離の証明ではない。
- 直近サイクル15 LLM calls、概算$0.002683。少量評価込み23 calls、概算$0.0036836。これはトークン単価計算で請求額ではない。
- 旧収束カウントは通信失敗や未検証claimを混同していた。新実装は検証済み状態の純増を数え、API失敗を収束と判定しない、旧カウントを継承しない。ただしverifiedへ進める処理が実運用上不在なら、この収束指標自体が機能しない可能性がある。
- brain_ragの既存索引はデフォルトでも_inbox草案を返した。今回は不採用としたが検索境界の実装修復は未実施。

## 質問

1. 次の一手を一つ選んで理由を示してほしい。A: 隣接領域の第3バッチ投入、B: 既存候補の検証・昇格経路、C: 候補／確定知識の検索・推論境界修復、D: 質問回答による再利用評価、E: その他。
2. 続く3段階を、具体的成果物・機械的な完了条件・失敗時の処理とともに提案してほしい。最初の半日〜1日で実施できる最小単位にしてほしい。
3. 安い生成器と検証器をどう分担すべきか。同じLLMで再判定するだけの自己確認や、引用一致だけの検証を避け、通常の人手承認も減らす設計にしてほしい。安価モデルの固有名や現在料金は資料から確認できる範囲のみ。
4. いま自動化を続けてよい処理、保留すべき処理、重大な見落としを区別してほしい。
5. 成功指標を最大5個。ノード数より、根拠追跡・検証精度・再利用・総費用を重視。未検証を verified と呼ばないこと。

日本語で1500〜2200字程度。最初に優先順位の結論を置く。提示された実測と推測を区別し、コード未読の項目は確認項目とする。改善案を一般論だけで終わらせず、今回の107 claims規模に合わせてほしい。
