loop:
1. **評価対象・予算・既存版を固定する**
   - 固定20問は変更せず、開発対象は優先5問 `E-02 / E-03 / E-05 / E-07 / E-08`。必要主張・合格条件・現時点の回答経路を記録する。
   - 現状申告を採用し、`K-0003 / K-0010` は承認済みとして版・根拠台帳を照合する。旧文書の `revise` へ機械的に戻さない。現行版の承認が確認できれば「3件中2件承認」の既存ゲートは通過済み。
   - 探索順は「承認済みカードの組合せ → 36候補の修正・統合 → 不足する独立主張の取得」。新カード作成を既定動作にしない。

2. **講義・一次資料・実務問題を共通形式へ取り込む**
   - MITは入力元の一つとする。講義は概念構造の取得、一次資料は根拠の確認、実務問題は制約・失敗例・検証課題の発見に使う。
   - 最小データ構造は次のとおり。
     ```text
     Source:
       id, kind[lecture|primary|practice], uri,
       locator, excerpt, version_hash, source_family

     Claim:
       id, version_hash, proposition,
       layer[evidence_claim|abstraction|application_hypothesis],
       scope, assumptions, limitations,
       source_ids, parent_claim_ids, derivation,
       review[pending|approved|revise|defer],
       validation[untested|supported_in_scope|refuted|inconclusive]

     Concept:
       id, claim_ids, aliases

     Relation:
       id, from, to,
       type[supports|contradicts|generalizes|analogous_to|depends_on],
       mapping, conditions, claim_ids, review

     Bundle:
       id, question_ids, concept_ids, relation_ids,
       hypothesis_ids, test_ids, answer_routes

     Test:
       id, hypothesis_id, environment, prediction,
       comparator, metric, pass_fail_rule,
       preregistered_at, result, evidence_ids
     ```
   - `evidence_claim`には実証・理論・定義の別と研究設計を付記する。**出所の種類と証拠の強さは別項目**とし、講義や実務記録を無条件に科学的事実へ昇格させない。
   - 同じ論文を引用した複数講義は、`source_family`で同根と判定する。

3. **主張を分離し、原子概念へ束ねる**
   - 根拠付き主張、そこからの抽象化、応用仮説を別レコードにする。現行の `lecture_derived` は出所属性へ移し、認識上の区分として使わない。
   - 原典本文の位置・短い引用・適用条件・限界まで確認する。検索断片だけなら根拠確認完了にしない。
   - 同義概念は統合し、カードは概念と主張への表示窓として扱う。カードが増えなくても、根拠・関係・回答経路が改善すれば成果とする。

4. **上位概念と横断関係を生成する**
   - 複数概念に共通する構造を、`abstraction`として作る。必須項目は「親概念」「保持する関係」「捨象する条件」「導出」「破れる反例」。
   - 横断原理の候補には、**少なくとも2領域の構造対応と1件の境界例・反例**を要求する。「似ている」は `analogous_to` であり、因果的根拠ではない。
   - 承認された抽象を次周回の入力にし、さらに上位化できる。ただし承認は導出・条件の妥当性を意味し、普遍的な実証済み原理を意味しない。
   - 導出関係は非循環にする。循環参照やAIによる言い換えを追加根拠として数えない。

5. **応用仮説を反証可能な形へ落とす**
   - 仮説は「対象環境・介入・予測・代替説明・比較対象・指標・棄却条件」を持つ。
   - 検証前に判定条件を固定する。理論なら証明と反例探索、実証なら独立データでの検証、実務なら過去事例・シミュレーション・許可済み実験を使い分ける。
   - シミュレーション成功は、そのモデル内の支持に限定する。概念の承認も、仮説の検証設計承認も、実務上の有効性承認へ拡張しない。

6. **同一版を二者が独立判定する**
   - Fable 5とGPT-6 Astraへ、束の差分・主張・根拠台帳・関係・検証計画を同じハッシュで渡す。互いの判定を見せずにレビューする。
   - 両者一致の場合のみ状態を更新し、不一致は `defer`。束全体の一括承認で、未確認の主張や関係を巻き込まない。
   - 二者一致は品質ゲートであり、独立した科学的証拠の代わりではない。

7. **検証・再利用を測り、失敗を次の入力にする**
   - 承認済みの主張・関係で評価回答を生成し、検証結果は支持・反証・判定不能のいずれも保存する。
   - 未達原因を「根拠不足／抽象化の誤り／関係不足／適用条件違反／知識の独立した欠落」に分類する。
   - 次の作業は、未達回答の修復、別課題への再利用、条件を保った重複統合への寄与を推定し、費用当たりの寄与が高いものから選ぶ。固定問題の改善だけでなく、未見課題への転用も測る。

initial_bundles:
以下は**抽出・統合する設計候補**であり、列挙概念の新規カード化を要求しない。カード本文・評価質問本文は未提示のため、接続は本文照合で確定する。特にK-0010の内容は推測しない。検証質問は束の内部テストであり、固定20問の差し替えではない。

1. **bundle:** 戦略的相互作用と選択環境
   - **atomic concepts:** 利得、最適反応、均衡、コミットメント、情報条件、個人最適と全体最適。K-0003を起点に既存候補を照合する。
   - **higher-order concepts:**  
     「自分の行動が相手の反応を通じて結果を変える意思決定」  
     →「行動そのものだけでなく、反応を生むルールを設計する」
   - **validation question:**  
     「競争施策と組織内の評価制度で、相手の反応を無視した最適化はいつ失敗するか。利得・情報・行動集合を対応付け、対応が破れる条件を示せるか」
   - **固定問との接続:** E-02。E-03は指定どおりK-0003とK-0010の組合せ経路を確認する。

2. **bundle:** 因果推定と介入の検証
   - **atomic concepts:** 反実仮想、交絡、選択バイアス、比較群、識別条件、効果の異質性、外的妥当性。K-0007を候補起点とする。
   - **higher-order concepts:**  
     「観測された差と、介入によって生じる差の分離」  
     →「意思決定に必要な因果主張を、識別可能な問いへ変換する」
   - **validation question:**  
     「生活上の選択支援と事業施策で、導入後の改善だけでは効果を断定できない理由を示し、どの比較と仮定なら識別できるか。識別不能なら保留できるか」
   - **固定問との接続:** E-05・E-07。E-08へは副作用・効果の波及を介して接続する。

3. **bundle:** フィードバック・副作用・適用範囲
   - **atomic concepts:** 状態変数、蓄積と流量、正負のフィードバック、遅延、波及効果、時間尺度、測定指標。まず36候補内の重複と不足を調べる。
   - **higher-order concepts:**  
     「局所的な介入効果は、相互作用・時間・境界条件で変わる」  
     →「施策と評価系を一緒に設計し、移植可能性を条件付きで判断する」
   - **validation question:**  
     「短期の指標改善が長期の全体改善を保証しない例を、業務運用と行動介入の2領域で構成できるか。副作用を生む経路、観測期間、仮説を棄却する結果を指定できるか」
   - **固定問との接続:** E-08を中心に、第1束の戦略的反応、第2束の因果検証へ接続する。因果関係が未確認のループ図は仮説として保持する。

agents:
- **Gemini Flash Lite：収集・一次分解**
  - 資料候補探索、原典位置取得、引用抽出、主張分割、出所系統の記録。
  - 検索範囲は未達主張から限定し、網羅収集しない。
- **Haiku：整理・機械検査の前処理**
  - 重複統合、3層分類、関係候補、適用条件の抜け、引用と主張の対応を検査。
  - 固定ルーブリックに従う評価案をJSON出力。承認権限は持たない。
- **Fable 5：概念設計・独立レビュー**
  - 上位概念の有用性、導出、横断対応、既存知識で代替できないかを評価。
- **GPT-6 Astra：反証設計・独立レビュー**
  - 根拠の射程、因果識別、反例、検証可能性、評価漏洩を重点評価。
  - Fable 5とともに最終判定するが、役割分担によって必須審査項目を省略しない。
- **決定論的オーケストレーター：状態と費用の管理**
  - ハッシュ固定、スキーマ検査、重複検出、判定突合、予算管理、評価集計、監査ログ。
  - 高価格モデルは設計各1回、3束を各モデルで初回＋修正時最大1回、最終判定各1回の**最大16呼出し**。差分を束単位でまとめる。
  - 人のカード承認工程は置かない。一方、未許可の実環境介入・課金・外部公開は自律実行しない。

stop_rules:
1. **増幅の限界:** 上位化は原子概念から最大3段、1段につき候補最大2案。2周連続で「未達回答の改善・実質的な再利用経路追加・条件を保った重複削減」がすべて0なら、その系統を停止する。
2. **根拠・判定の限界:** 根拠欠損、二者不一致、検証不能は修正1回まで。それでも解消しなければ `defer`。再開には新しい根拠・条件・検証手段を要求し、言い換えだけでは再投入しない。
3. **資源・権限の限界:** 14日、API・検索費の仮上限US$30、高価格モデル16呼出しのいずれかで停止する。予算は開始前に実単価で確認して固定する。使い切っても評価基準を下げず、未達として報告する。

two_week_check:
**Day 0に質問・ルーブリック・モデル設定・予算を固定する。** 利用課題10件もこの時点で固定し、最終評価までは知識生成エージェントへ渡さない。既存20問の残り15問は評価専用とし、パイロット通過までは知識拡張の対象にしない。

| 項目 | 14日後の合格条件 |
|---|---|
| 優先質問 | **5/5問合格**。承認済み知識による必須主張の充足と適用条件を、二者が同一ルーブリックで確認 |
| 根拠追跡 | 優先5問の主要な事実主張の**100%**が原典位置へ到達。抽象化の**100%**が親主張と導出へ到達 |
| 区分の維持 | 未検証仮説の事実扱い、類推の因果根拠扱い、承認版の取り違えが**0件** |
| 再帰的増幅 | **3束すべて**に承認済み上位概念が1件以上。各上位概念に**2領域の対応＋境界例・反例1件以上** |
| 仮説の検証 | **各束1件以上、合計3件以上**を事前登録して検証。反証・判定不能も実行成果に含め、支持件数は目標にしない |
| 未見課題への転用 | 利用課題**10件中8件以上**が、**新規外部検索0回**で合格。引用があるだけでは合格にしない |
| 実質的な再利用 | **3概念以上**が、それぞれ**別の2課題以上**で必須主張を支える。回答経路から除くと必須主張が欠けるものだけ数える |
| 回帰・費用 | 固定20問の合格数が初日以上、未回答は0点。**予算内・高価格呼出し16回以内** |

実施順は、**1〜3日目：版照合・分解、4〜9日目：3束の構築・レビュー、10〜12日目：検証・修正、13〜14日目：凍結版の最終評価**。

集計はログから自動化する。ただし、この合格は「根拠管理と再利用の運用品質」の合格であり、生成した横断原理や応用の普遍的な科学的妥当性を保証するものではない。
